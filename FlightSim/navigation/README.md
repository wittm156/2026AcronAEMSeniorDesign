# Navigation — Ollama Route Planning

A navigation module that interprets route requests, asks a local Ollama model to create waypoint coordinates, and prepares the resulting route for the simulator UI.

---

## Overview

The navigation feature supports:

- Destination selection using airport names, IDs, and aliases
- Direct routes from **KLVN (Airlake)** by default
- Waypoint coordinates generated by **Ollama / qwen3:4b**
- Distance calculations and route validation performed in Python
- Shared waypoint records for other modules in the running simulator

Complete the preflight checklist to reveal the route panel, enter a request such as `Shortest route to KSTP`, and click **Plan route**.

These routes are for visualization. Terrain, airspace, and flight procedures are not evaluated. The origin currently does not follow the live aircraft position.

## Navigation Logic Flow

1. **UI request:** `RoutePanel.plan()` reads the query and starts a background `RouteWorker` so model requests do not block the GUI.
2. **Airport loading:** The worker calls `database.load_database()` to obtain the origin and available airports.
3. **Destination extraction:** `OllamaQueryModel.parse()` asks Ollama to return a destination ID and routing preference.
4. **Python calculation:** Python calculates the direct great-circle distance and required waypoint count, allowing spacing margin below the 5 NM maximum.
5. **Waypoint generation:** A second request sends Ollama the original query, exact endpoints, calculated distance, and point count. Ollama returns the waypoint coordinates as named entries.
6. **Validation and packaging:** `planner.plan_route()` validates the coordinates, calculates distances along the returned route, adds altitude metadata, and builds GeoJSON geometry. Invalid geometry receives one correction request; a second failure is displayed as an error.
7. **UI and shared state:** `RoutePanel.show_route()` receives a successful result, updates `route_state.route_waypoints` in place, displays a summary, and emits `route_selected`.

Ollama creates the intermediate coordinates. Python calculates distances and formats the returned coordinates into waypoint records. There is no calculator tool-call loop.

## Airport Database (`database.py`)

Loads airport information directly from `ui/SyntheticVision/airports_save.json`; no separate database service is required.

### Responsibilities

- Define the default airport export location through `AIRPORTS_PATH`
- Select OpenStreetMap elements tagged as aerodromes, excluding runways
- Read coordinates from airport nodes or the center of ways and relations
- Skip records with no usable position and reject invalid coordinate ranges
- Choose airport IDs using ICAO, FAA, IATA, then an OSM identifier as a fallback
- Collect names and aliases so Ollama can interpret different destination names
- Reject duplicate airport IDs and ensure the selected origin exists

### Connection to the Code

`RouteWorker.run()` calls `load_database(path=None, origin="KLVN")` before querying the model. The returned dictionary contains `origin`, `airports`, and empty `waypoints` and `routes` placeholders. Each airport record includes `id`, `name`, `aliases`, `lat`, and `lon`.

## Ollama Query Model (`query_model.py`)

Coordinates destination interpretation, Python distance calculations, and model-generated waypoint coordinates.

### Responsibilities

- Connect to the local Ollama server using JSON HTTP requests
- Ask Ollama to extract a listed airport ID and supported routing preference
- Reject unknown destinations, unsupported preferences, and the origin as a destination
- Use `planner.distance_nm()` to calculate the distance sent to the model
- Calculate a waypoint count targeting 80% of the maximum spacing, leaving room for coordinate approximation
- Send only the resolved origin and destination records to the waypoint-generation request
- Require named waypoint entries through a response schema that fixes endpoint coordinates and entry IDs
- Convert returned entries into an ordered list without creating or replacing their coordinates
- Pass that list to `planner.plan_route()` and request one correction if validation fails
- Report HTTP errors and invalid response JSON to the UI worker

### Request Settings

- **Model:** `qwen3:4b`
- **Endpoint:** `http://127.0.0.1:11434/api/chat`
- **Timeout:** 180 seconds per HTTP request
- **Temperature:** 0
- **Streaming:** disabled

A successful request normally uses two model calls: destination extraction and waypoint generation. A coordinate correction adds one more call.

## Route Validation and Distance Calculations (`planner.py`)

Validates Ollama's coordinates and prepares a route result for the UI. This file does not call Ollama or generate intermediate coordinates.

### Responsibilities

- Calculate great-circle distances in nautical miles with `distance_nm()`
- Check destination availability and supported optimization
- Require between 2 and 2000 waypoint records with unique, nonempty IDs
- Reject missing, nonnumeric, nonfinite, or out-of-range coordinates
- Check that the first and last records match the origin and destination
- Enforce maximum leg spacing and reject excessive detours from the direct route
- Calculate cumulative distance at every returned waypoint and total route distance
- Add constant altitude metadata and create GeoJSON geometry for map consumers

### Settings

| Constant | Value | Purpose |
| --- | --- | --- |
| `WAYPOINT_SPACING_NM` | 5 NM | Maximum gap between consecutive points; validation allows 0.05 NM rounding tolerance. |
| `ROUTE_ALTITUDE_FT` | 1500 ft MSL | Constant visualization altitude added to every point, including endpoints. |
| `EARTH_RADIUS_NM` | 3440.065 NM | Spherical Earth radius used in great-circle calculations. |
| `ENDPOINT_COORDINATE_TOLERANCE_DEG` | 1e-9 degrees | Allows floating-point representation noise when checking exact airport coordinates. |

The returned route length may exceed the direct distance by at most 2%, with a minimum allowance of 0.1 NM. The altitude is not a terrain-clearance or takeoff/landing profile.

### Result Structure

`plan_route()` returns `origin`, `destination`, `selected`, and `alternatives`. The selected route contains:

- `points`: ordered airport and intermediate waypoint IDs
- `waypoints`: records with `id`, `lat`, `lon`, `altitude_ft`, and `distance_from_start_nm`
- `distance_nm`: Python-calculated distance along the returned coordinates
- `geometry`: a GeoJSON LineString using `[longitude, latitude]` coordinate order
- `waypoint_spacing_nm` and `altitude_reference`: route metadata

## Shared Route State (`route_state.py`)

Defines `route_waypoints`, the latest accepted waypoint list shared within the simulator process.

### Responsibilities

- Give other modules a stable list they can import and read
- Retain accepted waypoint records until the next planning request
- Support in-place UI updates so existing imports see the latest list contents

The UI clears this list when planning starts and updates it after success. It remains empty following a failed request. This module does not save routes to disk, synchronize separate processes, or persist across restarts.

### Usage

```python
from navigation.route_state import route_waypoints

# Read after a route has been accepted by the UI.
for point in route_waypoints:
    print(point["lat"], point["lon"], point["altitude_ft"])
```

For event-driven access, connect to `RoutePanel.route_selected` and read `result["selected"]["waypoints"]`.

## Automated Tests (`test_planner.py`)

Checks the Python planning behavior and Ollama request structure using mocked responses.

### Responsibilities

- Verify total and cumulative distance calculations
- Confirm that Python preserves the model's coordinates and does not mutate the original input
- Check rejection of missing points, wrong endpoints, excessive spacing, and invalid coordinates
- Verify that Python's calculated distance and endpoint constraints are sent to Ollama
- Check the single correction request for invalid waypoint geometry

The tests do not require a running Ollama server. They verify the code's behavior, not whether a real model will always return valid geometry.

### Run Tests

From the `FlightSim` directory, using the project's Python environment:

```powershell
python -m unittest navigation.test_planner
```

## Package Initialization (`__init__.py`)

Marks `navigation` as a Python package so other modules can use imports such as `from navigation.database import load_database`. It contains no route-planning or startup logic.

## Running Navigation

Install Ollama separately and download the model once:

```powershell
ollama pull qwen3:4b
```

Keep the Ollama application running, or start the server if one is not already running:

```powershell
ollama serve
```

Launch the simulator from `FlightSim` using the project's Python environment:

```powershell
python run_sim.py
```

Complete the preflight checklist and use the route panel. The panel displays the result or an error; the terminal prints route distance and waypoint details.
